# Расширенный поиск гиперпараметров

Эксперимент продолжает [небольшой подбор по CV](tuning.md) и
[оценку первых K клиентов](campaign.md). Цель — проверить более широкий набор
сочетаний параметров при ограниченном бюджете обучения.

## Протокол

- Данные и внешний split прежние: train — 4 225, validation — 1 409,
  test — 1 409 клиентов. Test не оценивался.
- На train используются те же пять стратифицированных фолдов с двумя
  повторениями, seeds 42 и 43. Это десять внутренних обучений на конфигурацию.
- Полный pipeline передаётся в CV. Медианы, масштабирование и категории
  обучаются заново только на обучающей части каждого фолда.
- RandomizedSearchCV выбирает заданное число сочетаний, seed поиска — 42.
  Основная метрика — средняя AP по десяти проверочным фолдам; ROC-AUC сохраняется
  как дополнительная. `refit=False`: поиск не обучает финальную модель сам.
- Прежний победитель CV каждой семьи включён первым отдельным кандидатом.
  Его десять оценок воспроизводятся и сверяются с `tuning.json`.
  При точном равенстве средней AP сохраняется первый кандидат.
- Выбор всех трёх конфигураций завершается до оценки validation. После этого
  прежние и выбранные варианты обучаются на полном train и оцениваются
  на validation по AP, ROC-AUC, метрикам при пороге 0.5 и top-K.
- K=50, 100, 200, 500 сохранены из предыдущего эксперимента. Порядок списка:
  риск по убыванию, ID по возрастанию при точном равенстве. Churn не участвует
  в ранжировании; для оценки top-K фиксированный порог вероятности не нужен.

## Пространства поиска

Диапазоны и бюджет заданы в коде перед запуском. Остальные настройки
и преобразования сохранены из предыдущего эксперимента.

| Семья | Сочетаний | Параметры |
|---|---:|---|
| Логистическая регрессия | 16 | C: loguniform от 0.001 до 1000; class_weight: None / balanced |
| Случайный лес | 24 | n_estimators: 200 / 300 / 500; max_depth: 4 / 6 / 8 / 12 / None; min_samples_leaf: 1 / 3 / 5 / 10 / 20; max_features: sqrt / 0.5 / 1.0; class_weight: None / balanced |
| Градиентный бустинг | 24 | learning_rate: loguniform от 0.01 до 0.2; n_estimators: 100 / 150 / 300 / 500; max_depth: 1 / 2 / 3 / 4; min_samples_leaf: 5 / 10 / 20 / 40; subsample: 0.7 / 1.0 |

Loguniform даёт равные вероятности интервалам с одинаковым отношением границ:
для C интервалы 0.01–0.1 и 10–100 имеют одинаковую вероятность.
Для леса случайно проверяются 24 из 450 дискретных сочетаний без повторений
внутри этого поиска. Для других семей непрерывные распределения не задают
конечную сетку. `max_features` леса применяется к столбцам после преобразований,
включая OneHotEncoder; 1.0 означает все такие столбцы, 0.5 — половину с округлением
вниз. `max_depth=None` снимает ограничение глубины, остальные условия остановки
деревьев сохраняются.

Итого: 64 × 10 = 640 обучений случайного поиска и 3 × 10 = 30 контрольных,
всего **670 обучений внутри CV**. Обучения на полном train для validation идут
дополнительно. Dummy prior повторно не настраивается; его прежняя AP validation
равна 0.26544. Для top-K остаётся математическое ожидание случайного отбора.

Алгоритм: [RandomizedSearchCV](https://scikit-learn.org/stable/modules/generated/sklearn.model_selection.RandomizedSearchCV.html),
выбор распределений: [руководство scikit-learn](https://scikit-learn.org/stable/modules/grid_search.html#randomized-parameter-optimization).

## Результаты CV

«Прежний» — победитель небольшого подбора, «после поиска» — победитель расширенного
сравнения внутри той же семьи. Средние AP относятся только к проверочным фолдам train.

| Семья | Прежняя средняя AP | После поиска | Изменение | SD после поиска |
|---|---:|---:|---:|---:|
| Логистическая регрессия | 0.66564 | 0.66578 | +0.00014 | 0.02330 |
| Случайный лес | 0.67134 | 0.67382 | +0.00248 | 0.01787 |
| Градиентный бустинг | 0.67387 | 0.67897 | +0.00510 | 0.01865 |

Выбранные параметры:

- Логистическая регрессия: C=4.676478725076045, class_weight=None.
- Лес: 200 деревьев, max_depth=8, min_samples_leaf=20, max_features=0.5,
  class_weight=None. Bootstrap сохранён.
- Бустинг: 300 деревьев, max_depth=1, min_samples_leaf=5,
  learning_rate=0.061721159481070736, subsample=1.0.

## Сравнение на validation

В таблице — AP и число ушедших среди первых K клиентов, до → после расширенного поиска.

| Семья | AP | TP@50 | TP@100 | TP@200 | TP@500 |
|---|---|---|---|---|---|
| Логистическая регрессия | 0.64279 → 0.64323 | 36 → 37 | 78 → 77 | 142 → 143 | 274 → 274 |
| Случайный лес | 0.64128 → 0.64195 | 43 → 44 | 78 → 78 | 140 → 140 | 273 → 276 |
| Градиентный бустинг | 0.64508 → 0.64967 | 43 → 45 | 76 → 77 | 142 → 141 | 275 → 274 |
| Случайный отбор: ожидание | — | 13.27 | 26.54 | 53.09 | 132.72 |

У выбранных вариантов ROC-AUC: 0.83643 / 0.83808 / 0.83965 соответственно.
Общая AP выросла у всех трёх семей, но улучшение не переносится на каждый K.
У логистической регрессии при K=100 найдено на одного ушедшего меньше; у бустинга
при K=200 и K=500 также на одного меньше. Лес сохраняет precision@100=78%,
recall@100=20.86% и lift@100=2.94. Лучшая AP остаётся у бустинга; при K=50 его
precision равна 90%, при K=100 — 77%.

У нового бустинга граница K=500 проходит внутри группы из 13 клиентов с одинаковым
риском: выбираются 12. Фиксированный порядок по ID даёт 274 ушедших; другой порядок
только внутри этой группы мог бы дать 273 или 274. Это диапазон последствий разрешения
равенства, не доверительный интервал. При K=200 в граничной группе два клиента,
оба попадают в список, поэтому число найденных ушедших от их порядка не зависит.
На остальных проверенных границах новых моделей равных рисков нет.

Расширение поиска дало умеренное улучшение AP бустинга (+0.00459 на validation)
и небольшие изменения у других моделей. Эти результаты сами по себе не подтверждают
статистической значимости различий и не определяют универсального лидера для любого K.

## Воспроизведение

```bash
python scripts/search_models.py
```

Нужны скачанный CSV, зависимости из requirements.txt и reports/tuning.json.
Скрипт проверяет SHA-256 данных, параметры прежних моделей, версии библиотек,
состав внешних частей и CV-фолдов. Старые метрики validation также должны
воспроизвестись. Расчёт использует два параллельных обучения; лес внутри одного
обучения использует до двух потоков.

Полный отчёт — [expanded_search.json](expanded_search.json): пространства,
реальные параметры всех проверенных вариантов, оценки каждого фолда, средние,
стандартные отклонения, выбранные индексы и validation-метрики. Обученные pipeline
сохраняются локально в `artifacts/expanded_selected_<семья>.joblib`, списки —
в `artifacts/rankings/expanded_*_validation.csv`. Файл
`artifacts/expanded_search_cv.json` сохраняет промежуточные результаты завершённых
семей; автоматического возобновления из него нет. Артефакты исключены из Git.

## Ограничения

Поиск ограничен выбранными диапазонами и бюджетом; глобально лучшие настройки
не установлены. Выбор максимума по CV делает оценку победителя оптимистичной.
Стандартное отклонение по зависимым фолдам не является доверительным интервалом.

Validation уже использовалась на предыдущих этапах разработки и не заменяет
финальную независимую проверку. В этом запуске она не участвует в выборе
гиперпараметров. Различия в несколько клиентов в top-K не доказывают устойчивого
превосходства. Риск оттока не оценивает эффект удерживающего предложения.
Итоговая модель для сервиса и окончательный режим отбора пока не зафиксированы.
